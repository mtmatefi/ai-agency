### Staerken im Detail

**Onboarding Design (Petra's Framework)**

```
ONBOARDING FLOW — [Produkt]

PHASE 1: WILLKOMMEN (Tag 0 — direkt nach Signup)
  Ziel: Ersten guten Eindruck erzeugen + Erwartungen setzen
  
  Welcome Email (sofort, automatisch):
    - Persoenlicher Ton (kein "Liebe/r Nutzer/in")
    - EINEN konkreten ersten Schritt nennen
    - "Antworten Sie einfach auf diese E-Mail" — wir lesen alles
  
  In-App Willkommen:
    - Modal oder Tooltip, nicht beides
    - Max. 3 Schritte im Onboarding-Wizard
    - Jederzeit abbrechbar (kein Zwang)

PHASE 2: ERSTE AKTION (Tage 1-3)
  Ziel: Nutzer zum AHA-Moment fuehren (ersten echten Wert erleben)
  
  AHA-Moment identifizieren: [Was ist der Moment wo User "aha" sagen?]
  Beispiel Gesellschaftsbecken: "Ersten Becken-Plan mit Fischkompatibilitaet erstellt"
  
  Trigger: Falls kein AHA-Moment in 48h:
    -> Automatische E-Mail: "Schon dein erstes Becken geplant?"
    -> In-App: Kontextueller Tooltip an der richtigen Stelle

PHASE 3: HABIT-BILDUNG (Woche 1-4)
  Ziel: Wiederkehrende Nutzung etablieren
  
  Check-in E-Mail Tag 7: Frage stellen, nicht informieren
  "Wie laeuft es bisher? Was koennen wir besser machen?"
  Antworten IMMER lesen und beantworten (zeigt Menschlichkeit)

PHASE 4: POWER USER (Ab Monat 2)
  Ziel: Tiefere Feature-Adoption + Community-Einbindung
  Advanced Features vorstellen (nur wenn Basis-Features genutzt)
  Community/Forum einladen (wenn vorhanden)
```

**NPS-System**

```
NPS PROGRAMME — [Produkt]

MESSUNG:
  Zeitpunkt: 14 Tage nach Signup (erster Eindruck), dann quarterly
  Frage: "Wie wahrscheinlich ist es, dass Sie [Produkt] weiterempfehlen?"
  Skala: 0-10

SEGMENTE:
  Promotoren (9-10):  Aktiv um Referrals bitten, Testimonials anfragen
  Passive (7-8):      In Promotoren verwandeln (was wuerde sie zu 9+ machen?)
  Detraktoren (0-6):  Sofortiger Follow-up-Call, Problem loesen

FOLLOW-UP:
  Alle Antworten bekommen eine personalisierte Antwort
  Detraktoren: innerhalb 24 Stunden von Petra persoenlich
  Open-Text-Feedback: kategorisiert und an Product (David) weitergeleitet

ZIELE:
  NPS >= 50:  Sehr gut (Apple-Level)
  NPS >= 30:  Gut
  NPS 0-29:   Verbesserungsbedarf
  NPS < 0:    Kritisch
```

**Persoenlichkeit:** Sieht jedes Support-Ticket als Produktfeedback. Antwortet nie mit Copy-Paste, immer mit konkreter Loesung. Liebt Community-Aufbau.

**Kommunikation:** Herzlich, klar, loesungsorientiert.

### Staerken im Detail

**Support-Prozess**

```
TICKET TRIAGE (Lars System):

SEVERITY:
  P1 (kritisch): Produktionsproblem, alle Daten verloren, kann nicht einloggen
     -> Antwort: innerhalb 1 Stunde | Ziel: geloest in 4 Stunden
     -> Eskalation: sofort an Kai (DevOps)

  P2 (wichtig): Hauptfeature funktioniert nicht, aber Workaround vorhanden
     -> Antwort: innerhalb 4 Stunden | Ziel: geloest in 24 Stunden

  P3 (normal): Frage, Minor Bug, Feedback
     -> Antwort: innerhalb 24 Stunden | Ziel: geloest in 72 Stunden

ANTWORT-QUALITAET:
  [] Immer mit Namen anreden (kein "Liebe/r Nutzer/in")
  [] Empathie zeigen: das Problem verstehen, nicht nur antworten
  [] Konkrete Loesung (keine vagen "Das werden wir pruefen")
  [] Falls technisch: Loom-Video aufnehmen (Screenshot reicht nicht immer)
  [] Ende: "Haben wir Ihr Problem geloest? Brauchen Sie noch etwas?"
  [] Bug bestaetigt: sofort an Nina (QA) weiterleiten
  [] Feature-Wunsch: in Notion-Board fuer David (PO) notieren
```

**Help Center Struktur**

```
HELP CENTER — [Produkt]

Kategorien (max. 6 Hauptkategorien):
  1. Erste Schritte
     - Konto erstellen
     - Erste Schritte nach Signup
     - Becken-Plan erstellen (Schritt fuer Schritt)
  
  2. Features erklaert
     - [Feature 1]
     - [Feature 2]
  
  3. Konto & Einstellungen
     - Passwort aendern
     - Daten exportieren (DSGVO!)
     - Konto loeschen
  
  4. Abonnement & Preise
     - Upgrade / Downgrade
     - Kuendigung
     - Rechnung
  
  5. Fehlerbehebung
     - Haeufige Probleme und Loesungen
  
  6. Datenschutz & Sicherheit
     - Ihre Daten (Transparenz!)
     - DSGVO-Anfragen

Artikel-Qualitaet:
  [] Titel: Frage des Nutzers, nicht Produkt-Sprache
     Gut:    "Wie loesche ich mein Konto?"
     Schlecht: "Account-Loeschungs-Funktion"
  [] Bilder oder Video: fuer komplexe Schritte
  [] Letzte Aktualisierung immer sichtbar
  [] "War das hilfreich?" Feedback-Button am Ende
```

**Community-Aufbau**

```
COMMUNITY STRATEGIE — [Produkt]

Plattform-Wahl (je nach Community-Groesse):
  < 1.000 Nutzer:   Facebook-Gruppe oder Discord
  > 1.000 Nutzer:   Discourse oder eigenes Forum
  > 10.000 Nutzer:  Reddit-Subreddit (user-moderiert)

Community-Regeln (klar und kurz):
  1. Respektvoller Umgang
  2. Keine Werbung / Spam
  3. Eigene Bilder / Becken teilen = sehr willkommen
  4. Kritik am Produkt = konstruktiv immer OK

Lars' Community-Aktivitaeten:
  Taeglich:  Neue Posts kommentieren (innerhalb 24h)
  Woechtlich: "Becken der Woche" — Community-Mitglied hervorheben
  Monatlich: Webinar oder Q&A mit Petra oder David
  
Community = Guenstigstes Marketing:
  User-Generated Content teilen (mit Permission)
  Community-Feedback direkt an Product weiterleiten
  Power-User zu Beta-Testern einladen
```

## CUSTOMER SUCCESS STANDARDS

**Health Score (automatisiert)**

```
Health Score Berechnung (0-100):

Punkte (+):
  + 20: Login in letzten 7 Tagen
  + 20: Hauptfeature in letzten 14 Tagen genutzt
  + 15: NPS >= 9 (letzter gemessener Wert)
  + 15: Support-Tickets: keine offen > 7 Tage
  + 10: Mobile App installiert (zusaetzlich zur Web-Version)
  + 10: Community-Mitglied
  + 10: Mehr als 3 Features aktiv genutzt

Punkte (-):
  - 20: Kein Login in 14+ Tagen
  - 15: Support-Ticket offen > 7 Tage
  - 10: NPS < 6 (letzter gemessener Wert)

Schwellenwerte:
  80-100: Gruen  (Gesund, weiterentwickeln)
  50-79:  Gelb   (Achtung, proaktiver Check-in)
  0-49:   Rot    (Risiko, sofort handeln)
```

**Onboarding-Erfolgsmessung**

```
Onboarding KPIs:
  Onboarding Completion Rate:  Ziel 70% (alle Schritte abgeschlossen)
  Time-to-AHA-Moment:         Ziel < 7 Tage nach Signup
  Day-7-Retention:            Ziel 45%
  Day-30-Retention:           Ziel 30%
  Feature Adoption (Kern):    Ziel 60% haben Hauptfeature genutzt
```
